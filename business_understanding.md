# 1. Бизнес-анализ (Business Understanding)

**Название проекта:** AI-система оценки финансового риска и поведенческого профиля клиента.

## 1.1 Организационная структура

Проект реализуется в рамках финансовой организации (банк или финтех-компания), предоставляющей кредитные продукты физическим лицам.

### Участники проекта со стороны заказчика

- Бизнес-заказчик — кредитный департамент / риск-менеджмент (определяет бизнес-правила и KPI).
- Владелец продукта (Product Owner) — отвечает за внедрение модели в бизнес-процессы.
- Риск-аналитики — эксперты в области кредитного скоринга и оценки дефолтных рисков.
- Data Engineering команда — обеспечивает доступ к данным и их подготовку.
- IT / ML инженеры — реализация модели и интеграция в систему принятия решений.

### Основные пользователи системы

- Кредитные менеджеры (при ручном рассмотрении заявок).
- Автоматизированная система скоринга (API для принятия решений о выдаче кредита).
- Риск-аналитики (для мониторинга качества портфеля).

### Бизнес-цель проекта

**Основная цель:**

Повышение качества оценки кредитного риска клиентов за счет построения AI-системы, учитывающей поведенческие и транзакционные финансовые данные.

**Дополнительные бизнес-цели:**

- Снижение уровня дефолтов по кредитам.
- Выявление клиентов с неформализованными или недекларированными источниками дохода.
- Повышение точности кредитного скоринга.
- Снижение финансовых потерь организации.
- Улучшение сегментации клиентов по уровню риска.

### Существующие решения

В настоящее время в организациях подобного типа используются следующие подходы:

- **Rule-based системы**
  - Принятие решений на основе фиксированных правил (доход, возраст, кредитная история).
  - Ограниченная гибкость и слабая адаптация к новым паттернам поведения.
- **Классические скоринговые модели**
  - Логистическая регрессия и scorecard-модели.
  - Используются как baseline, но имеют ограниченную выразительность.
- **ML-модели (частично внедренные)**
  - Градиентный бустинг (XGBoost, LightGBM).
  - Используются для кредитного скоринга, но без глубокого анализа транзакционного поведения.

**Ограничения существующих решений:**

- Слабый учет поведенческих паттернов клиента во времени.
- Отсутствие анализа транзакционных аномалий (вне зарплатных поступлений).
- Ограниченная способность выявлять скрытые или нестандартные источники дохода.
- Недостаточная интерпретируемость сложных моделей.

## 1.2 Текущая ситуация (Assessing Current Solution)

### Данные

**Используемые источники данных:**

- Анкета клиента (демографические и социальные данные).
- Кредитная история (займы, просрочки, долговая нагрузка).
- Транзакционные данные (входящие и исходящие операции).
- Поведенческие данные (активность клиента в системе).

**Временные данные (Kaggle):**

- `Lending Club` -> кредитный риск.
- `PaySim` -> транзакции / аномалии.


### Ресурсы

**Инфраструктура:**

- Использование облачных вычислений (CPU достаточно для базовых моделей).
- GPU не является критически необходимым (если не используются нейросети).


### Риски проекта и их минимизация

#### 1) Риск несоблюдения сроков

**Причины:**

- Задержка доступа к данным.
- Сложность интеграции источников данных.

**Митигация:**

- Использование открытых датасетов (например, Lending Club).
- Поэтапная реализация (MVP -> расширение).

#### 2) Риск низкого качества данных

**Причины:**

- Пропуски, шум, несогласованность источников.
- Неполные транзакционные данные.

**Митигация:**

- Этап Data Cleaning и Feature Engineering.
- Использование устойчивых агрегированных признаков.

#### 3) Риск слабой предсказательной способности модели

**Причины:**

- Недостаточная информативность признаков.
- Слабая связь между поведением и дефолтом.

**Митигация:**

- Расширение признакового пространства (поведенческие + транзакционные фичи).
- Использование ансамблевых моделей.

#### 4) Риск отсутствия интерпретируемости

**Причины:**

- Сложность моделей (градиентный бустинг, ансамбли).

**Митигация:**

- Использование SHAP / feature importance.
- Комбинирование с интерпретируемыми моделями.

## 1.3 Data Mining Goals

### Приоритет реализации (MVP)

- **Приоритет MVP:** кредитный скоринг (бинарная классификация дефолта).
- **Второй этап (после MVP):** модуль выявления аномалий транзакционного поведения.
- На этапе MVP критерии успеха и основные ресурсы фокусируются на задаче скоринга.

### Тип задачи

Проект включает две взаимосвязанные задачи:

- **Бинарная классификация** — прогноз вероятности дефолта клиента (0/1).
- **Выявление аномалий транзакционного поведения:**
  - Обнаружение нетипичных финансовых поступлений.
  - Выявление потенциально недекларированных доходов.

### Метрики качества

**Для задачи кредитного скоринга:**

- AUC-ROC (основная метрика).
- Precision / Recall (в зависимости от бизнес-рисков).
- F1-score (баланс классов).

**Для задачи выявления аномалий:**

- Precision@K (качество топ-N подозрительных случаев).
- Recall (способность находить аномалии).

### Критерий успешности

- AUC >= 0.75 — приемлемый результат модели.
- AUC >= 0.80 — высокий уровень качества.
- Улучшение по сравнению с baseline (логистическая регрессия ~0.65-0.70).

**Дополнительно:**

- Снижение доли ложноположительных решений.
- Устойчивость модели на разных сегментах клиентов.

## 1.4 План проекта (Project Plan)

Проект реализуется по этапам CRISP-DM:

1. **Business Understanding**
   - Постановка бизнес-целей и требований.
2. **Data Understanding**
   - Анализ источников данных.
   - Исследование распределений и качества данных.
3. **Data Preparation**
   - Очистка данных.
   - Обработка пропусков.
   - Создание признаков:
     - Поведенческие метрики клиента.
     - Транзакционные агрегаты.
     - Признаки аномалий доходов.
4. **Modeling**
   - Baseline модель: Logistic Regression.
   - Основные модели: Random Forest, XGBoost / LightGBM.
   - Модель аномалий: Isolation Forest / One-Class SVM (этап расширения после MVP).
5. **Evaluation**
   - Оценка качества по AUC / Precision / Recall.
   - Анализ ошибок модели.
   - Интерпретация результатов (SHAP).
6. **Deployment (концептуально)**
   - Развертывание модели как API-сервиса.
   - Интеграция в систему принятия кредитных решений.
   - Мониторинг качества модели.

**Порядок внедрения:**

1. MVP: скоринговая модель (кредитный риск).
2. Расширение: подключение аномалий как дополнительного риск-сигнала.
